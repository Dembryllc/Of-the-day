# OfTheDay.net — Session 2026-08-25 → 08-27

Covers seven commits, `57818ad` → `ab8fadb`. Written retroactively on
2026-09-18: this stretch shipped without a session log, so the details below
are reconstructed from commit bodies, CI runs, and the live Stripe account.

## The headline: payments were never actually wired up

Live Stripe keys had been active since 2026-07-05, and checkout worked — real
cards were chargeable. But **every registered webhook endpoint was test mode**,
so `stripeWebhook` had never once been invoked in production. A real payment
would have taken the money and never set `tier: 'pro'`. Nobody had paid yet, so
nobody was harmed, but the product was one customer away from that.

Fixed across four commits:

1. **`bf01b26` — Remove dead-on-arrival Firestore write from `onUserCreate`.**
   The Admin SDK write (`plan:'trial'` + `trialStartedAt`) had been failing
   `PERMISSION_DENIED` on *every* signup since it was written — the Gen 1
   auth-trigger service account has no Firestore access, unlike Gen 2 functions.
   Trials were never broken, because `AuthScreen.jsx` and `App.jsx`'s
   `onAuthStateChanged` fallback both already write those fields client-side
   under the user's own auth. Removing the redundant write killed the error-log
   noise without touching any IAM. (If server-side trial setup is ever wanted
   back, the real fix is granting `oftheday-c6490@appspot.gserviceaccount.com`
   the Cloud Datastore User role — not re-adding this write as-is.)

2. **`c9022e7` — Register the live webhook endpoint.** `we_1U8VdEB2eRKsbhTpKzrx1k12`
   ("OfTheDay production") → `https://stripewebhook-qznlc6fzoa-uc.a.run.app`,
   events `checkout.session.completed`, `customer.subscription.updated`,
   `customer.subscription.deleted`. `STRIPE_WEBHOOK_SECRET` rotated to the new
   endpoint's signing secret and redeployed — each endpoint has its own secret,
   so rolling it or adding another endpoint means updating the secret again or
   every event 400s.

   The API version is pinned to **2017-06-05** deliberately, to match the old
   test endpoints: newer versions moved `current_period_end` off the
   subscription onto its items, which would break the `sub.current_period_end`
   read in the handler.

3. **`90ae376` — Fix the handler crash the first real payment exposed.** Live
   mode has no synthetic test events, so proving this took an actual live
   subscription (free at the time — `trial_period_days: 14` means $0 due
   today). The event verified fine, then the handler threw:

   ```
   Cannot use "undefined" as a Firestore value (found in field "currentPeriodEnd")
   ```

   Firestore discards the **entire** `set()` on one undefined value, so the
   paying user never got `tier:'pro'` — a 500, which Stripe then retried.

   Root cause is subtler than the pin suggests: pinning the *endpoint* to
   2017-06-05 preserves the old shape for **event payloads only**.
   `stripe.subscriptions.retrieve()` is a separate API call that uses the
   **SDK's** version (`stripe@^22`), where the top-level field is gone. Fix is
   `periodEndOf(sub)` reading
   `sub.current_period_end ?? sub.items?.data?.[0]?.current_period_end ?? null`.
   The `?? null` is load-bearing. Re-check this if the endpoint's API version
   or the stripe package is ever bumped.

4. **`7ce5094` — Record it as proven.** Full chain verified end to end:
   `checkout.session.completed` delivered → 200 `{received:true}` → Firestore
   `tier:'pro'` → app showed Pro.

## Also shipped

- **`57818ad` — Four QA bugs** found in a thorough app review:
  - Routines page rendered its entire topbar block twice (title, subtitle,
    grade filters).
  - `.settings-details-body` was unconditionally `display:flex`, so closed
    accordion content still laid out and peeked past the card's
    `overflow:hidden` into the next card (Sync / Data & Backup overlap). Now
    scoped to the open `<details>`.
  - Lesson Slides "+ New" silently wiped an in-progress or AI-generated slide;
    now confirms first.
  - Do Now's ELA / Science / Social Studies tabs are unimplemented but looked
    identical to broken links — added a "Soon" badge + tooltip. Also hardened
    `loadOnThisDay` against a stale-response race where an in-flight fetch from
    an older grade context could overwrite state after a newer request started.

- **`4dd092a` — Subscription management in the profile sheet.** There was no way
  for a subscriber to cancel. Adds a Subscription section opening the
  Stripe-hosted billing portal (update card, view invoices, cancel), backed by a
  new `createPortalSession` callable that verifies the caller owns the account.
  Hidden in demo mode, where there is no uid to bill.

  The sheet is bottom-anchored with no max-height and no scroll, so its footer
  (Save Changes / Sign out) could be pushed off-screen with no way to reach it
  on short windows — and adding anything to the body made that certain. Now
  capped at 92vh with the body scrolling.

- **`ab8fadb` — Projector slide readability (2026-08-27).** Body text bottomed
  out at ~18px on a 1080p smartboard while ~80% of each column sat empty: the
  clamp caps were tuned for a laptop preview and header sizes never scaled at
  all. Measured at true 1080p, then raised the clamps. Sizes are vmin-based, so
  these figures are what they render as at 1920×1080 (vmin = 10.8), not
  literals in the source: learning target 54px (`clamp(24px, 5vmin, 76px)`),
  body 32px (`clamp(15px, 3vmin, 44px)`), column header 22px — up from roughly
  32 / 18 / 19px.

  That alone regressed the long-content case: column 3 stacks three sections in
  the height columns 1–2 give to one, and `studentTask` allows 300 chars vs 250,
  so max-length lessons clipped their last line — silently losing content
  mid-lesson. Column 3 now binary-searches the largest font size at which all
  three sections fit — `useFitFontSize`, 14 iterations, testing
  `scrollHeight <= clientHeight + 1`, bounded by `min(22, max(11, 1.5·vmin))`
  and `min(36, max(13, 2.5·vmin))`. At 1080p that range is ~16–27px: typical
  lessons get the 27px ceiling, worst-case settle near 20px instead of
  truncating. Re-fits on resize. Verified at 1920×1080 and 1366×768 with
  typical and max-length content.
